# Board targets and builds

All WR targets use the same pinned WR core, firmware overlays and host/WR
clock crossings. Board clock actuators and physical connections differ:

| Target | FPGA / PHY | WR clock control | Console / WR SFP |
| --- | --- | --- | --- |
| `acorn_wr_nic.py` | CLE-215+, XC7A200T / GTP | Main and helper MMCM; optional main GTP TXPI | Baseboard Mini USB UART; SFP0 |
| `spec_a7_wr_nic.py` | SPEC-A7 / GTP | Main AD5683R ×2, helper AD5683R ×1 | USB UART; SFP0 / J12 |
| `hyvision_pcie_opt01_revf.py` | XC7K70T / GTX | Main and helper MMCM | DVP UART; SFP0 / CN1, or `--sfp 1` for CN2 |
| `acorn_liteeth_nic.py` | CLE-215+, XC7A200T / GTP | Ethernet only, no WR | Baseboard Mini SFP0 and SFP1 |
| `spec_a7_liteeth_nic.py` | SPEC-A7 / GTP | Ethernet only, no WR | SFP0 / J12 |
| `spec_a7_bringup.py` | SPEC-A7 XC7A35T / optional GTP | Bring-up SoC, no WR | USB UART; optional Ethernet on `--eth-sfp 0` (J12) or `1` |

`spec_a7_platform.py` defines board resources; it is not a separate design.
The WR wrapper supports Artix-7 GTP and Kintex-7 GTX. The direct TXPI backend
is GTP-specific; HyVision tunes its GTX reference with the MMCM backend.

Acorn and SPEC-A7 have been exercised as both WR master and slave. HyVision
needs hardware qualification of link acquisition, tuning range and both
roles. A successful FPGA build does not establish WR lock, independent PPS
alignment or jitter. Absolute accuracy requires the board/module delay and
link asymmetry calibration, checked with an independent timing instrument.

## Reproducible WR build

Install the clean Python repository revisions listed in
[wr_bench_sources.json](wr_bench_sources.json), plus the listed Vivado and
RISC-V toolchain versions. Use an isolated environment or `PYTHONPATH` so
these revisions take precedence over other editable installations. The
firmware builder obtains its pinned WRPC revision and submodules; the core
builder obtains the pinned WR HDL revision and submodules. A reused WR HDL
checkout at a different revision is rejected with recovery instructions.

From the repository root, build sequentially: firmware filenames are shared
between boards. Choose a new output directory for each build:

```sh
python3 tools/build_wr_bench.py --board acorn --output build/wr-acorn
python3 tools/build_wr_bench.py --board spec --output build/wr-spec
python3 tools/build_wr_bench.py --board hyvision --output build/wr-hyvision
```

This helper verifies the Python revisions, builds the default uRV/private
128 KiB profile and checks the final Vivado timing report. Firmware flash
writes/erases are disabled and calibration changes stay in RAM. The output
contains the programming image, matching CSR map, firmware and a manifest
with source revisions and image hashes. Keep generated evidence under
`build/`, outside commits.

For Acorn's optional TXPI actuator:

```sh
python3 tools/build_wr_bench.py --board acorn --wr-refclk-tuning txpi --output build/wr-acorn-txpi
```

`--pll-trace-decimation 16` also enables the SoftPLL trace and FPGA sensors.
SPEC's trace profile omits the PCIe NIC/PTM to fit the device; use the default
profile to check the full NIC build. See [PLL capture](wr_loop_response.md).

For normal firmware with persistent storage, build through the board target:

```sh
python3 acorn_wr_nic.py --build --skip-software-headers --output-dir build/acorn
python3 spec_a7_wr_nic.py --build --skip-software-headers --output-dir build/spec
python3 hyvision_pcie_opt01_revf.py --build --skip-software-headers --output-dir build/hyvision
```

These targets build board-specific firmware automatically. When reusing
separately built firmware, pass `--skip-firmware-build` and use the matching
`--target acorn`, `spec_a7` or `hyvision` in `litex_wr_nic/firmware/build.py`.
The optional CPU/memory configurations are described in
[WR integration](wr_integration.md) and the README; their resource and timing
checks are separate from the default board profile.

## Connections and tuning

The [USB bench guide](wr_usb_bench.md) covers Acorn/SPEC SRAM programming,
stable UART paths, role selection and per-board master trim. It requires USB
UART/JTAG, compatible SFP modules and fiber, without a PCIe host connection.
For a physical XC7A35T SPEC, use the converted `.bin` generated by the helper;
the NIC targets synthesize for XC7A50T. Do not load the unconverted 50T `.bit`
onto a 35T. The bring-up target builds for 35T directly.

HyVision needs an external 3.3 V USB-UART adapter and common ground:
DVP.DTX / FPGA T19 is TX; DVP.DRX / U19 is RX. The shared WR/LiteX UART uses
115200 baud. JTAGBone uses J11 or J13; the target header documents the pinout.
PPS is DVP.LVAL / U20, and the WR reference clock is DVP.FVAL / T18.
The platform defines separate `sfp_mod_abs` and rate-select pads; module
presence uses `sfp_mod_abs`, with RS0/RS1 driven low for 1.25 Gb/s operation.

HyVision's MMCM commands now use `WRMMCMBackend`, crossing coherently from
`wr_sys` to the 200 MHz PSCLK. Integer MMCM division is required for fine
phase shifting. The nominal command rate is
`abs(code - 32768) / 2**19` phase shifts per PSCLK, with one outstanding
shift and a completion watchdog. This replaces the legacy `ps_gen` cadence;
old trim and loop measurements must be repeated. The `hyvision` firmware
profile starts with the Acorn MMCM PI settings, pending hardware tuning.
Neither board should use another unit's master trim as a universal default.

GTX readiness clears immediately on loss of reset completion or CPLL lock,
and asserts after synchronization to the recovered RX clock.

The GTX wrapper selects `GTGREFCLK` for the fabric-generated reference and
`GTREFCLK0` for a dedicated reference, following
[UG476](https://docs.amd.com/v/u/en-US/ug476_7Series_Transceivers).
Vivado reports the existing fabric-reference DRC (REQP-49 on GTP, REQP-52
on GTX): this clock input is intended for test use and has lower performance
than a dedicated transceiver reference. Build success does not qualify its
optical performance or jitter.

Acorn SFP EEPROM routing still requires the baseboard jumper/physical checks
in [the bench guide](wr_usb_bench.md); a WR link alone does not verify module
identification or a calibration database match.

## Ethernet and bring-up builds

These designs do not include WR firmware or the WR console:

```sh
python3 acorn_liteeth_nic.py --build --skip-software-headers --output-dir build/acorn-liteeth
python3 spec_a7_liteeth_nic.py --build --skip-software-headers --output-dir build/spec-liteeth
python3 spec_a7_bringup.py --build --output-dir build/spec-bringup
python3 spec_a7_bringup.py --build --with-hyperram --with-etherbone --output-dir build/spec-bringup-etherbone
```

For the bring-up SoC, `--with-ethernet` selects the CPU Ethernet path instead
of Etherbone. Install the LiteX CPU software dependencies and a compatible
RISC-V compiler for this target's BIOS. HyperRAM uses a direct, uncached bus.
With Ethernet enabled, its fabric PLL reference uses the QPLL `GTGREFCLK`
input. Inspect final timing and utilization for the exact options you build.
